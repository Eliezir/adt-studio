A melhor forma de relatar um bug, pedir um recurso ou sinalizar algo confuso é
**abrir um issue no GitHub**. Os issues são públicos, pesquisáveis e permitem que a equipe
acompanhe e responda ao seu relato. Você não precisa ser desenvolvedor — esta página
explica o passo a passo do zero.

## Criar uma conta no GitHub

Se você ainda não tem uma, vai precisar de uma conta gratuita no GitHub.

<Steps>

<Step>
### Acesse a página de cadastro

Abra [github.com/signup](https://github.com/signup) no seu navegador.
</Step>

<Step>
### Informe seus dados

Forneça um endereço de e-mail, uma senha e um nome de usuário. O GitHub enviará um código
para o seu e-mail para confirmar que é mesmo você.
</Step>

<Step>
### Verifique e conclua

Insira o código recebido por e-mail. Pronto — agora você tem uma conta no GitHub e
pode criar issues.
</Step>

</Steps>

<Callout title="Já tem uma conta?">
Basta [entrar](https://github.com/login) e pular para a próxima seção.
</Callout>

## Abrir um issue

<Steps>

<Step>
### Abra a página de issues

Acesse o rastreador de issues do projeto:
[github.com/unicef/adt-studio/issues](https://github.com/unicef/adt-studio/issues).
</Step>

<Step>
### Pesquise primeiro

Digite algumas palavras-chave na caixa de busca para verificar se alguém já
relatou a mesma coisa. Se encontrar um issue correspondente, adicione um comentário ou uma reação
👍 em vez de abrir um duplicado — isso ajuda a equipe a avaliar quantas
pessoas são afetadas.
</Step>

<Step>
### Escolha um modelo

Clique no botão verde **New issue**. Você será solicitado a escolher o modelo
que corresponde ao que está relatando — escolha o mais próximo:

- **Bug Report** — algo não está funcionando como deveria.
- **Feature Request** — sugira um novo recurso ou melhoria.
- **Accessibility Issue** — relate uma barreira de acessibilidade no aplicativo
  ou em um livro que ele gerou.
- **Documentation Issue** — algo nesta documentação está errado, confuso ou
  faltando.
- **Question / Support** — pergunte como fazer algo no ADT Studio.
</Step>

<Step>
### Preencha o formulário

Cada modelo é um formulário curto que pede exatamente o que a equipe precisa,
então basta seguir os campos. Algumas dicas para um relato fácil de tratar:

- **Um título claro** — resuma em uma linha (por exemplo, *"O áudio não é gerado
  em português"*).
- **O que aconteceu vs. o que você esperava.**
- **Passos para reproduzir** — o que você clicou, na ordem, para que a equipe
  consiga ver o problema também.
- **Sua configuração** — seu sistema operacional (Windows, macOS ou Linux) e a
  versão do ADT Studio.
- **Capturas de tela ou uma gravação de tela** — arraste os arquivos de imagem
  direto para a caixa de texto. Uma imagem costuma explicar mais do que um
  parágrafo.
</Step>

<Step>
### Envie

Clique em **Submit new issue**. Você receberá um e-mail sempre que alguém responder, e
poderá responder direto da sua caixa de entrada ou na página do issue.
</Step>

</Steps>

<Callout type="warn" title="Não inclua informações sensíveis">
Os issues são públicos. Nunca cole senhas, chaves de API ou dados pessoais em um
issue — borre ou remova essas informações das capturas de tela primeiro.
</Callout>
