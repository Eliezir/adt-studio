# @adt/site — ADT Studio public site (landing + docs)

The public-facing site for ADT Studio: the **landing page**, the **releases** pages, and the **documentation** (`/docs`) — all one app, one build, one deploy.

> Writing or translating documentation **content**? See **[`content/README.md`](./content/README.md)**. This file is about how the *app* is built and shipped.

---

## 1. What it is

| | |
|---|---|
| **Framework** | [TanStack Start](https://tanstack.com/start) (Vite) — file-based routes in `src/routes`, prerendered to a **static SPA** |
| **Docs** | [fumadocs](https://fumadocs.dev) (notebook layout) over MDX in `content/docs` |
| **Styling** | Tailwind CSS, Atkinson Hyperlegible font |
| **i18n** | [Lingui](https://lingui.dev) for UI strings + fumadocs per-locale MDX — `en`, `pt-BR`, `es`, `fr` |
| **Hosting** | GitHub Pages (static), served under `/<repo>/` |

It replaces the old `apps/landing` Vite SPA — landing **and** docs now live together so they share the design system, navigation, search, and language switcher.

```
apps/site/
├─ src/
│  ├─ routes/            ← pages (/, /download, /releases, /docs, /docs/$, …)
│  ├─ components/        ← landing sections + docs UI (components/docs/*)
│  ├─ i18n/              ← locales.ts (supported locales), setup.ts (client locale)
│  ├─ locales/           ← Lingui catalogs (en/es/fr/pt-BR .po) for UI strings
│  └─ lib/               ← source.ts (fumadocs source+i18n), docs-i18n.ts, layout.shared.tsx
├─ content/
│  ├─ README.md          ← docs authoring guide (write/translate pages)
│  └─ docs/<locale>/…    ← the documentation content (MDX)
└─ scripts/check-translations.mjs   ← docs translation-coverage linter
```

## 2. Develop

```bash
pnpm --filter @adt/site dev          # dev server (prints the local URL)
pnpm --filter @adt/site build        # static build → .output/public
pnpm --filter @adt/site preview      # serve the built output
pnpm --filter @adt/site run types:check
pnpm --filter @adt/site extract      # update UI string catalogs (.po)
node apps/site/scripts/check-translations.mjs   # docs translation coverage
```

> `src/routeTree.gen.ts` is generated by the Vite plugin (gitignored). A standalone `types:check` needs a prior `build` to generate it — CI builds first for that reason.

## 3. Internationalization

The site has **one locale**, shared between the landing and the docs (the globe switcher; persisted in `localStorage` + `?lang=`). Locales are defined once in `src/i18n/locales.ts`.

- **UI text** (components, chrome): Lingui macros → `src/locales/*.po`. CI fails on unwrapped/unextracted strings.
- **Docs content** (MDX): per-locale folders `content/docs/<locale>/…` (fumadocs `parser: 'dir'`), with per-page English fallback and a per-locale search index.

Full authoring workflow (adding pages, translating, `meta.json`): **[`content/README.md`](./content/README.md)**.

## 4. Deploy & branch model

The site is **not** deployed from `main`. It lives on a long-lived standalone branch and ships from there.

- **Deploy branch:** **`landing-page`**. It is **never merged into `main`**, so `main` stays in sync with upstream. Develop on `landing-page-v1` (or a feature branch) and **open a PR into `landing-page`** to publish.
- **`landing-page` is protected** — PRs only, no direct commits.
- **Workflows** (`.github/workflows/`, present on the deploy branch only):
  - `site.yml` — on push to `landing-page` (or manual `workflow_dispatch`): builds with `BASE_PATH=/<repo>/`, writes a `404.html` SPA fallback (so unknown URLs boot the app and redirect home), uploads `apps/site/.output/public`, deploys to Pages.
  - `site-ci.yml` — on `landing-page-v1` pushes and PRs into `landing-page`: build, type-check, unextracted-strings check, translation-coverage linter.
- **Result URL:** `https://<owner>.github.io/<repo>/` (e.g. `https://unicef.github.io/adt-studio/`).

### Prerequisites (one-time, GitHub settings)

- **Pages source = GitHub Actions** (Settings → Pages).
- The **`github-pages` environment** must allow the `landing-page` branch in its deployment-branch policy — otherwise the build succeeds but the deploy step is rejected.

### Troubleshooting

- **Build passes, deploy fails / "branch not allowed":** add `landing-page` to the `github-pages` environment's deployment-branch policy.
- **`Cannot find module './routeTree.gen'` in type-check:** run a build first (the route tree is generated by the Vite plugin).
- **Deep links 404 on Pages:** ensure the `404.html` step ran (`cp _shell.html 404.html`).
- **Rolling the branch back doesn't change the live site:** Pages keeps the last deployed artifact — re-run the relevant deploy workflow to change what's published.
